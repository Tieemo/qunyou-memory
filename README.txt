# 项目：群友卡牌 Memory 小游戏（微信小程序）

## 目标
开发一个微信原生小程序（WXML/WXSS/JS，不用任何框架、不用云开发、不用后端），实现一套变体记忆翻牌游戏，并内置图鉴系统。美术资源已备好，放在 /assets/ 目录（卡背 back.png、各好人卡 face/*.png、各神人卡 trap/*.png），文件名即卡牌ID。

## 核心规则（已实现为常量，禁止改动）
- 卡牌成对。每回合玩家翻2张：
  - 相同好人卡 → 留在场上明牌，+1分
  - 相同神人卡 → 留在场上明牌，0分
  - 不同好人卡 → 盖回，0分
  - 好人+神人 → 盖回，-1分
  - 不同神人卡 → 盖回，-2分
- 图鉴：玩家翻到某卡第一张后，自己3个回合内翻到第二张配对成功 → 解锁该卡图鉴。好人卡神人卡都可解锁。
- 全部卡配对完，游戏结束，展示总分+已解锁图鉴。分数可为负。

## 需要做的页面（3个，tab或页面跳转均可）
1. 游戏页：网格牌阵（数量按屏幕自适应，建议4x4或4x5，难度可选卡池大小）、回合/分数显示、翻牌动画（翻转+盖回）、结束弹窗。
2. 图鉴页：全部卡牌网格，未解锁显示卡背剪影+问号，已解锁显示卡面，标注"好人/神人"。
3. 首页：开始游戏（选难度）、进入图鉴。

## 数据与存储
- 卡池配置：assets 文件名列表写进一个 config.js，方便后续加卡。
- 图鉴解锁状态 + 历史最高分 → wx.setStorageSync 本地持久化。
- 无网络请求、无登录、无任何后端依赖。

## 验收标准
- 真机/模拟器可完整跑通一局，计分与扣分逻辑与规则表完全一致。
- 图鉴解锁逻辑符合"3回合内"判定。
- 刷新小程序后图鉴与最高分不丢失。
- 资源用本地相对路径，不写死绝对路径。

## 发挥空间（可自主决定）
- 翻牌/配对的动画与音效细节
- 计分飘字、连击提示等反馈
- UI风格（建议贴合卡牌二次元画风）
- 简单AI陪玩或纯单人模式二选一，选实现成本低的

## 网页版（Gitee Pages）
入口是仓库根目录的 index.html，卡图在 assets/。改规则或卡池后运行：
  python tools/build_web.py
本地可直接用浏览器打开根目录 index.html。
